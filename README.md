# imgfit

**把每张图片精确压进指定大小预算的本地工具** —— 默认 200KB，一句命令批量处理，全程离线。

给网申、报名、政务系统上传材料用的：那些系统普遍限制单张 200KB / 500KB / 1MB，
而手机拍的成绩单、证书动辄 5~8MB，用普通压缩软件要么压不达标，要么把字糊掉。

```text
imgfit 材料/            # 压到 200KB，结果进 材料/压缩/
```

没有第三方依赖（除 Pillow），没有云服务，没有联网校验，图片不出你的电脑。

## 它和"普通图片压缩"的区别

普通压缩是"给你一个质量参数，自己试"。imgfit 反过来：**你给字节上限，它自己找参数**。

* 对每个候选组合**真编码一次**、量真实字节数，不做公式估算（JPEG 体积估算误差常达 20%~30%）
* 两个自由度里，**优先权衡的是分辨率而不是画质**——因为文字材料的可读性几乎全在分辨率上
* 已经达标的小图**不做二次有损压缩**，按字节原样复制
* 落盘后再自检一遍：字节数达标、能完整解码、尺寸对得上

## 30 秒上手

### 图形界面（推荐给不熟悉命令行的场景）

```bash
python -m imgfit --gui
```

Windows 上双击 `run-gui.bat` 也可以（自动带上 `src` 路径，不用先安装）。
选文件 → 填目标大小 → 开始压缩 → 看结果 / 打开输出目录 / 导出 CSV。

### 命令行

```bash
# 1. 最常用：整个文件夹压到 200KB
imgfit 材料/

# 2. 指定预算和输出目录
imgfit 材料/ -t 500kb -o 输出/

# 3. 先看计划，不动文件
imgfit 材料/ -n

# 4. 总预算模式：不管单张多少，总量不能超过 2MB
imgfit 材料/ --total 2mb

# 5. 顺手导出一份 Excel 能直接打开的报表
imgfit 材料/ --report 压缩报告.csv
```

## 安装

需要 Python 3.9+。

```bash
git clone https://github.com/xiaomei004/imgfit.git
cd imgfit

# 方式一：装成一个命令（推荐）
pip install -e .
imgfit --help

# 方式二：不安装，直接用
#   macOS / Linux：
PYTHONPATH=src python -m imgfit --help
#   Windows PowerShell：
$env:PYTHONPATH="src"; python -m imgfit --help
#   Windows 上更省事：直接双击 run-gui.bat / 把文件夹拖到 run-cli.bat 上
```

> `pip install -e .` 第一次会在构建隔离环境里下载 `setuptools`（Python 3.12 起的 venv 默认不带它），
> 需要联网一次；之后离线也能正常用。想完全离线就用方式二或两个 `.bat`。

> Windows 下如果 `tkinter` 缺失（某些精简版 Python 会有），`--gui` 会提示改用命令行，CLI 功能不受影响。

## 参数

| 参数 | 说明 |
| --- | --- |
| `inputs...` | 图片文件或文件夹，可给多个 |
| `-o, --output DIR` | 输出目录，默认是输入目录下的 `压缩/` |
| `-t, --target SIZE` | 单张大小预算，`200kb` / `1.5mb` / `204800`（默认 `200kb`，KB=1024） |
| `--total SIZE` | 总预算，按每张原图大小自动分配（"装水"算法） |
| `--headroom SIZE` | 预留余量，默认自动（200kb 目标留 5kb） |
| `--mode {resolution,quality}` | `resolution`=分辨率优先（文档/证书，默认）；`quality`=质量优先（照片） |
| `--min-quality N` | 质量下限，默认 40 |
| `--target-quality N` | quality 模式的保底质量，默认 75 |
| `--max-dim N` | 长边上限像素，默认 2200 |
| `--floor-dim N` | 长边下限像素，默认 800 |
| `--background COLOR` | 透明图转 JPEG 的填充底色，默认 `white` |
| `--keep-metadata` | 保留 EXIF/ICC（默认清除） |
| `--no-copy` | 已达标也重新编码（默认原样复制） |
| `-f, --overwrite` | 覆盖同名产物（默认自动加 `(1)` 后缀） |
| `--no-recursive` | 不递归子文件夹 |
| `-j, --jobs N` | 并行进程数，默认 1 |
| `-n, --dry-run` | 只打印计划，不写文件 |
| `--report PATH` | 导出 `.csv` 或 `.json` 报告 |
| `-q / -v` | 精简 / 详细输出 |
| `--gui` | 打开图形界面 |
| `--version` | 版本号 |

退出码：`0` 全部成功 · `1` 有文件失败（其余仍已完成） · `2` 参数错误。

## 两种模式怎么选

| | `resolution`（默认） | `quality` |
| --- | --- | --- |
| 优先保住 | 画面像素（长边） | 编码质量（≥75） |
| 适合 | 成绩单、证书、证件、扫描件、截图 | 照片、作品图、需要细腻渐变的素材 |
| 代价 | 质量可能降到 40，边缘会有轻微块状 | 分辨率会明显变小，细字可能看不清 |

同一张 981KB 的成绩单、同样 195KB 预算，两种模式的差别：

| 方案 | 分辨率 | 视觉效果 |
| --- | --- | --- |
| resolution（采用） | 934×1320 | 表格里的分数、课程名清晰可读 |
| quality（保底 q75） | 707×1000 | 无块状伪影，但字明显更小更糊 |

判断依据是"信息在哪"：文字类材料的信息密度高、对比强，降低质量仍可辨认；
照片的细节分散在灰阶里，先降质量就会出现色块。详细实验数据见
[`docs/设计说明.md`](docs/设计说明.md)。

## 默认行为的几个考量

**为什么留 5KB 余量**：`200KB` 有两种算法——`200×1024 = 204800` 和 `200×1000 = 200000`。
不同系统校验代码各不相同，留出余量后两种口径都能过（输出最大 199609 字节）。

**为什么清除 EXIF**：手机拍的材料带 GPS、设备型号、拍摄时间，部分机型甚至写入序列号。
求职材料外传时这些信息没有理由跟着走。需要保留（比如带版权信息的摄影作品）就加 `--keep-metadata`。

**为什么已经是小图就不再压**：JPEG 每次转码都是又一次有损。已在预算内的图直接按字节复制，
画质零损失，还能省时间。

**为什么重复运行会生成 `(1)`**：默认不覆盖任何已有文件（包括源文件本身永远不被动），
确认要覆盖就加 `-f`。

### 目录结构

```text
src/imgfit/
├── size.py       # "200kb" → 204800 的解析与格式化
├── engine.py     # 核心：预算内的（分辨率 × 质量）搜索、编码、自检
├── pipeline.py   # 批量编排：收集文件、预算分配、并行、报告
├── cli.py        # 命令行界面
└── gui.py        # Tkinter 图形界面
tests/            # 65 个单元测试
docs/设计说明.md   # 算法取舍与实测数据
```

## 已知限制

* 输出统一为 JPEG。要保留 PNG 无损 / 透明通道，这个工具不适用。
* 预算极小（例如 5KB）且内容极复杂时，会明确报错"预算过小"，不会偷偷交付超标文件。
* `--total` 是按原图大小比例分配的，不区分内容类型；要精细控制请分两批跑、各自给预算。
* 一次处理上百张建议 `-j 4`；GUI 里固定单进程（Windows 下多进程与 Tk 同存容易出坑）。
* 在 cmd 里把输出重定向到文件（`imgfit ... > log.txt`）时，中文是否乱码取决于系统代码页；
  设 `set PYTHONUTF8=1` 即可（两个 `.bat` 启动脚本已经替你设好）。
