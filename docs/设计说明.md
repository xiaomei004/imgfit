# 设计说明

记录 imgfit 的几个关键取舍、以及支撑这些取舍的实测数据——避免以后（或者别人）凭直觉改坏它。

## 1. 问题定义

输入：一张图 + 一个字节上限 `B`。
输出：一张在视觉上尽量"够用"的 JPEG，且 `file_size ≤ B`。

"够用"没有普适定义，所以这里把它拆成两个互相排斥的指标：分辨率与编码质量。
工具提供两种模式，各自最大化其中一个，另一个只保底。

## 2. 为什么不信公式

常见的做法是按 `宽×高×每像素比特数 / 质量系数` 估算体积。JPEG 是熵编码，
实际字节数取决于图像局部高频成分的多少：

* 一张纯白 A4 扫描件在 quality=90 下可能只有 150KB
* 同尺寸的树叶特写在同一参数下能有 3MB

同一张成绩单，在 quality 固定 80、只改分辨率时，体积变化也完全不是线性的
（下表，单位 KB，实测于 1358×1920 的成绩单扫描件）：

| 长边 | q90 | q80 | q70 | q60 |
| --- | --- | --- | --- | --- |
| 2000 | 864 | 685 | 587 | 506 |
| 1600 | 716 | 519 | 420 | 358 |
| 1400 | 569 | 410 | 331 | 280 |
| 1200 | 431 | 309 | 250 | 211 |
| 1000 | 304 | 217 | 173 | 144 |

所以 imgfit 不做估算：**对每个候选参数真编码一次，用返回的字节串长度判断**。
代价是 CPU 时间，换来的是"绝不会交付超标文件"。

## 3. 两个自由度，信息分布决定优先级

预算固定时，能调的只有分辨率与质量。两者对"能否看清"的贡献完全不同：

**文字类材料**（成绩单、证书、证件、截图）
黑字白底、对比极强，压缩伪影主要出现在文字边缘。分辨率减半 = 笔画直接被抽掉，
再怎么提高质量也救不回来；而质量从 90 降到 40，字依然是字。

**照片类材料**
细节分布在连续灰阶里，质量过低会出现大面积色块、天空出现阶梯状条纹，
而分辨率不足只是"看起来小一号"，观感损失小得多。

同一张 981KB 成绩单、同样 195KB 预算下的三个候选（放大 2 倍对比过文字区域）：

| 方案 | 分辨率 | 质量 | 结论 |
| --- | --- | --- | --- |
| 分辨率优先（采用） | 934×1320 | q40 | 课程名、分数、印章文字均可辨认 |
| 中间点 | 849×1200 | q57 | 略软，可读性稍差 |
| 质量优先（保底 75） | 707×1000 | q74 | 无块状伪影，但字太小 |

这就是默认值选 `--mode resolution` 的原因；反过来，处理照片请显式用 `--mode quality`。

## 4. 搜索算法

参数空间是离散网格：长边从 `min(原图, 2200)` 递减到 `floor_dim`（默认 800），步长 50；
质量从 92 递减到 40，步长 2。

**分辨率优先**：长边从大到小遍历，对每个长边找"塞得下的最大质量"。
关键优化是先试最低质量——如果连 q40 都超标，这个长边直接跳过，只花 1 次编码。
只有"有希望"的长边才做质量二分（约 5~6 次编码）。实测单张图总编码次数 17~18 次。

**质量优先**：质量从保底值开始，对每个质量二分查找"塞得下的最大长边"
（体积随分辨率单调递增，二分成立）。典型 7~10 次编码。

**兜底**：所有网格都失败时，还会向下探到 `hard_min_dim`（320px），
再失败就抛 `FitError` 并报出"最小也需要多少字节"，绝不返回超标文件。

所有编码结果按 `(长边, 质量)` 缓存，同一个组合不会编两次。

## 5. 预算分配（`--total`）

总预算固定时用"装水"式分配，而不是简单平分：

1. 平分剩余额度
2. 本身就不超过均摊额度的文件，只拿自己那份（反正会原样复制，多给没意义）
3. 省下的额度回流，继续平分给还没满足的大文件
4. 直到所有文件都满足或额度耗尽

效果：10 张图里有 3 张本来只有 80KB，那 3 张不会占用 200KB 的额度，
剩下的预算全部给真正需要压缩的大图。每个文件保底 4KB。

## 6. 正确性保障

* **原子写入**：先写 `xxx.jpg.part`，`fsync` 后再 `os.replace`，中途断电不会留下半个文件
* **落盘自检**：写完重新打开、完整解码、比对字节数与尺寸，任何一项不符即判失败
* **源文件保护**：目标路径与源文件相同时强制改名；`-f` 也不会覆盖源文件本身
* **失败隔离**：单张坏图只记录在报告里，整批继续跑，退出码 1 提示有失败
* **幂等**：默认输出目录（`输入/压缩`）在收集阶段被排除，重复运行不会把上次的产物当输入

## 7. 隐私

默认清除 EXIF 与 ICC。手机拍摄的材料通常带 GPS 坐标、设备型号、拍摄时间，
部分机型还会写入序列号；求职、报名的材料外传时没有理由带上这些。
需要保留（例如带版权信息的摄影作品）用 `--keep-metadata`。

附带好处：清掉这些数据本身也能省几百字节到几 KB。

## 8. 试过但否掉的方案

| 方案 | 否决原因 |
| --- | --- |
| 拉色阶/提对比度去扫描水印 | 实测体积只降 1%~2%，水印是灰度中值而非接近白色，拉不掉 |
| 高斯模糊去噪 | 体积能降 15%~20%，但会把文字边缘磨软，可读性下降；只在极端情况下才值得 |
| 转灰度 | 体积可省近一半，但成绩单和证书上的红章是真实性凭证，灰度化等于毁证据 |
| 用估算公式代替实测 | 误差 20%~30%，必然出现"以为达标实际超标" |

## 9. 以后可以加的东西

* `--mode auto`：用白底占比 + 边缘密度判断"文档还是照片"，自动选模式
* WebP / AVIF 输出（同体积画质更好，但网申系统普遍不收）
* 拖拽进货（需要 `tkinterdnd2`，会破坏"零额外依赖"）
* PyInstaller 单文件 exe（给完全没装 Python 的电脑用）
* 多核跑满（现在 `-j` 已有，但默认 1 是为了可预测的耗时与日志顺序）
